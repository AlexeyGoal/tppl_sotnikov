# Задача 1

## Парадигма
Функциональная + Параллельная

## Язык программирования
C++ (в связке с CUDA/OpenCV)

## Обоснование
1. **Экстремальный поток данных:** Поток 100 кадров в секунду с разрешением 4096×4096 и 16 бит на пиксель генерирует около 3.35 Гбайт «сырых» данных в секунду ($4096 \times 4096 \times 2 \text{ байта} \times 100 \text{ кадров}$). Языки с автоматическим сборщиком мусора (Garbage Collector), такие как Java или C#, вызовут микрозадержки, что приведет к потере кадров. C++ дает полный контроль над памятью.
2. **Математическая обработка:** Математический анализ дефектов изображений требует параллельных вычислений. На C++ можно легко задействовать SIMD-инструкции процессора или перенаправить потоки данных напрямую на ядра видеокарты через CUDA.
3. **Парадигма:** Функциональная парадигма (чистые функции обработки без побочных эффектов) гарантирует, что детекция брака на одном кадре никак не испортит данные другого кадра. Параллельная парадигма необходима для распределения кадров по разным потокам вычислений, обеспечивая стабильную работу 24/7.

# Задача 2

## Парадигма
Объектно-ориентированная + Скриптовая

## Язык программирования
Python

## Обоснование
1. **Жесткий дедлайн (MVP за 2 недели):** Python обладает самым низким порогом входа и высокой скоростью написания кода. Синтаксис позволяет сосредоточиться на логике прогнозирования, а не на системных настройках.
2. **Готовые ML-библиотеки:** В индустрии машинного обучения Python — безоговорочный лидер. Нам сразу доступны мощнейшие инструменты: `scikit-learn`, `XGBoost`, `Pandas` для обработки датчиков и `TensorFlow` / `PyTorch`. Написать это с нуля за 2 недели на других языках невозможно.
3. **Быстрая итерация:** Прогноз нужен всего 1 раз в сутки, поэтому высокая скорость выполнения кода на этапе MVP не критична. Гораздо важнее возможность быстро менять алгоритмы, дообучать модели и проверять гипотезы "на лету".

# Задача 3

## Парадигма
Реактивная + Компонентная

## Язык программирования
TypeScript (Фреймворк React или Angular с библиотекой RxJS)

## Обоснование
1. **Высокая нагрузка на интерфейс (50+ виджетов):** Приложение получает плотный поток данных из WebSocket и REST API. Реактивная парадигма (например, потоки данных RxJS) идеально создана для управления асинхронными событиями. При изменении данных в одном источнике, другие виджеты автоматически "реагируют" и обновляются.
2. **Мгновенный отклик (< 16 мс):** 16 миллисекунд — это время одного кадра при частоте обновления экрана 60 Гц (1000 мс / 60). Чтобы интерфейс не лагал, TypeScript в связке с современными движками браузеров позволяет точечно обновлять компоненты (через Virtual DOM или Signals), не перерисовывая всю страницу целиком.
3. **Тестируемость:** Разделение UI на независимые компоненты и вынос бизнес-логики в чистые реактивные потоки позволяет легко покрывать код Unit-тестами.

# Задача 4

## Парадигма
Процедурная 

## Язык программирования
C

## Обоснование
1. **Жесткие ограничения по памяти:** У микроконтроллера всего 32 КБ оперативной памяти (RAM) и 256 КБ постоянной (Flash). Любые тяжелые языки с ООП-надстройками или виртуальными машинами просто не поместятся в чип. Язык C компилируется в максимально компактный машинный код.
2. **Энергоэффективность и Детерминированность:** Для работы от батарейки контроллер нужно вовремя погружать в режим глубокого сна и мгновенно будить по прерываниям от таймера или ADC (АЦП). Язык C гарантирует детерминированное (строго предсказуемое) время отклика без скрытых задержек.
3. **Доступ к железу и переносимость:** C позволяет работать напрямую с регистрами через указатели. При этом код легко перенести на архитектуру другого микроконтроллера (например, с STM32 на ESP32 или Миландр), просто перекомпилировав его под нужное ядро и заменив файлы конфигурации регистров (CMSIS/HAL).
